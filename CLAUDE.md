# Rugby 08 → browser (static recompilation)

Objective: run the full Rugby 08 (PE32 x86, MSVC 7.1, D3D8/DInput/DSound) in a browser on localhost, with all original content, by statically recompiling `Rugby08_unpacked.exe` to C and compiling it with emscripten. The source is public (GitHub IFAKA/rugby08-web, branch `main`); the game itself is never deployed.

## Commands (`./init.sh` is the single entry point; one summary line each, details in `logs/`)
- `./init.sh status` / `next`: pass/fail per features.json item and the next runnable one.
- `./init.sh check <id>`: run one item's check (log: `logs/check_<id>.log`); `check-all`: regression guard over every passing item.
- `./init.sh build-native` (CMake → `build/native/rugby08`, GL 4.1 via SDL2) · `build-web` (runs `tools/lift/split_big.py`, then emcmake → `build/web`) · `serve [port]` (localhost with COOP/COEP).
- `./init.sh lint [--report|--fix]` · `./init.sh structure [--report]`.
- One automated native run: `tools/check/run_native.sh --frames N [--replay tests/replays/X.txt] [--screenshot F] [--expect 'TEXT']` (hidden, muted). Web run: `tools/check/web_check.sh --expect 'TEXT'`.
- Regenerate `gen/recomp` from the exe: `tools/lift/lift_fixpoint.sh` (catalog + lift to a fixed point, slow: use `krn exec --cache`); sound-bank code: `tools/lift/aems_lift.py`. `gen/runtime/` (import bridges, D3D8 vtables) is regenerated by CMake from `tools/gen/`.
- Lift correctness: `tools/lift/difftest.py` (lifted C vs Unicorn on the same input), `tools/lift/fidelity_report.py`.
- `scripts/play.sh` is the user's interactive native build with sound (see "Play build is shared": never break it mid-session). `scripts/run.sh` drives unattended sessions.
- Python tools use `.venv/bin/python`. `init.sh` puts openjdk@21 and Ghidra's `analyzeHeadless` on PATH.

## Big picture (details: `docs/ARCHITECTURE.md`, ABI: `runtime/DESIGN.md`, exe facts: `REVERSE.md`)
- `tools/lift/` drives pcrecomp's `lift32` over the Ghidra catalog (`analysis/lift_catalog.json`). Our extensions add Pentium Pro x87/integer semantics (`lift_ext.py`), rewrite protector (SecuROM) call sites (`code_patch.py`, `stubemu.py`) and handle jump tables. The output is `gen/recomp/*.c`, about 4.2M lines.
- Guest model: registers are `_Thread_local` globals (built with `-DRECOMP_LOCAL_REGS -fwrapv -fno-strict-aliasing`). Guest memory is one arena at `g_mem_base` (4 GiB mmap natively, 1 GiB on wasm) with the PE image copied to VA 0x400000..0x1465000. Indirect calls go through `RECOMP_ICALL(va)`, which looks up manual, then generated, then import tables.
- Win32/COM boundary: IAT slots and COM vtables hold "bridge" VAs (0xFFF00000 imports, 0xFFE00000 COM). The bridges are generated `void f(void)` stdcall shims that read args from the guest stack. Callbacks into the game use `guest_call(va, …)`. Imports without a bridge log `UNIMPL dll!name` once.
- Graphics: `runtime/d3d8/` converts D3D8 calls to the renderer's D3D9 subset (`render/webgl/`), following d3d8to9's conversion rules. Shaders: the game's own D3DX assembles vs.1.1 → MojoShader → GLSL; fixed function is emulated in `render/webgl/glsl/`. Natively `platform/native/gl_native.c` rewrites GLSL ES to 4.10 core.
- Determinism: `RT_DET=1` (virtual clock plus guest scheduler, `runtime/core/det.c`) makes runs reproducible. Regress and the lockstep online mode depend on it. Debug probes (`RT_PROBE`, `RT_COVERAGE`, `tools/hooks.json`) live in `runtime/debug/README.md`.
- Other worktrees (`git worktree list`: online, online-ha, tidy) carry parallel branches. Confirm which tree you're in before editing.

## Session protocol (every session)
1. `krn context --json`, then `tail -40 PROGRESS.md`, then `krn state show` if present.
2. Pick the first item in `features.json` with `"passes": false` whose `deps` all pass. Work on only that item until its `check` passes.
3. Run the item's `check` command. Set `"passes": true` only if it exits 0. Never mark an item passed on judgment alone.
4. Commit (code and docs only), append 3–5 lines to PROGRESS.md (what changed, what you learned, next item), then continue with the next item in the same session.
5. If blocked (the same item failed 3 approaches, or it needs the user), write `BLOCKED: <item id> — <exact reason>` at the top of PROGRESS.md, record it with `krn state add negative "..."`, and move on to an independent item if there is one.

## Context rules (the filesystem remembers; the context window only reasons)
- NEVER Read whole: `gen/**`, `analysis/**`, `ghidra/**`, `logs/**`, `third_party/**` sources larger than ~300 lines. Query them: `jq` for one record, `rg -m 20`, `sed -n A,Bp`, `tail`, `krn find QUERY --json --max-files N`.
- Every script in `tools/` and `init.sh` prints ONE summary line to stdout and writes details to `logs/<name>.log`. Keep it that way for new scripts.
- Heavy deterministic steps (analyze, lift, big builds) run via `krn exec --cache --input <each input> -- <cmd>` so repeats are free.
- Mechanical edits: `krn code replace|insert-before|insert-after|remove`. Checks: `./init.sh check <id>` or `krn verify --level fast --json`.
- Subagents: Explore only for wide sweeps where you need a conclusion, not file dumps. Once the runtime interfaces in `runtime/include/` are stable, independent shims (d3d8, dinput, dsound, win32 kernel/user) may run as parallel worktree subagents, each owning its own feature ids.
- Use `krn state` only for irreducible facts: objective, constraints, proven facts, dead ends.

- Verification referee: behavior checks (trace logs, frame hashes, screenshots), never "it looks right".

## Layout and structure (docs/ARCHITECTURE.md; every source dir has a README.md)
- `runtime/` Win32/DirectX for the game (`core/ win32/ d3d8/ debug/ include/`) · `render/webgl/` the renderer
  (D3D9 subset on GL) · `platform/` host differences (`sdl/` shared, `native/`, `web/`) · `tools/` by job
  (`lift/ gen/ check/ web/ analysis/ oracle/`) · `tests/replays/` scripted input.
- `third_party/` submodules (pcrecomp, xboxrecomp, d3d8to9, mojoshader) · `analysis/ gen/ build/ logs/` ignored.
- Rules, enforced by `./init.sh structure` and `./init.sh lint`: hand-written files <= 300 lines, one job per
  file; `runtime/` is target-neutral (`__EMSCRIPTEN__` only in `platform/` and `render/`); debugging tools only in
  `runtime/debug/`; new dirs get a README.md; run `./init.sh lint --fix` before committing.
- Refactors (anything that must not change behaviour): `tools/check/regress.sh capture DIR --full` with the old
  and the new binary, then `compare`: deterministic runs must match pixel for pixel and hash for hash.

## Standing instruction (from the Opus 5.5 prompting guide, for unattended runs)
A standing instruction from the user, the person you are working for. It is about how your turns end. A message with no tool call in it ends your turn, and the work stops there until you are asked to continue. The user has seen you end turns in four ways while work they asked for was still owed, and does not want any of them. One: a long summary of what was done that closes by announcing the next step and has no tool call, so the next thing never starts. Two: an offer to carry on with something unless the user would prefer otherwise, which stops to wait for an answer the user was not going to give. Three: a list of decisions for the user when, by your own account, none of them blocks the rest of the work. Four: deciding that this is a good place to report, because the turn has been long or a milestone is done. Status notes are welcome, and so are your recommendations on open decisions, but put them in the same message as your next tool call and carry on with whatever does not depend on the user's answer. If you notice yourself inviting the user to redirect you or offering to wait, delete it and do the next thing. The stops the user does want are the ones where nothing can move without them, or where the thing blocking you is deliberately protected from you. This does not override the need for confirmation on risky or destructive actions.
